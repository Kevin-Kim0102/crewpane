# crewpane

让 Codex 调用本机 Claude Code 或 Kiro CLI 完成编码和测试，并通过网页面板查看任务、对话和执行结果。

**本项目定位为 Subagent 工作台，仅用于执行主 Agent 委派的任务。** 建议由 Codex 等主 Agent 拆解需求、派发任务、协调编码与测试，并审核和最终验收；不建议直接把本项目作为主 Agent 独立完成开发。

## 1. 启动面板

需要 macOS 或 Linux、Python 3.9+，以及 Claude Code 或 Kiro CLI。CLI 的安装方法也可在面板的“CLI 连接”中查看。

```bash
git clone https://github.com/Kevin-Kim0102/crewpane.git
cd crewpane
python3 -m crewpane start
```

打开命令返回的地址，默认是 [http://127.0.0.1:47831/](http://127.0.0.1:47831/)。服务在后台运行，可以关闭终端；已启动时会复用现有面板。

旧版的 `coder-agents` 命令和 `python3 -m coder_agents` 入口仍可使用，已有配置会继续沿用。

## 2. 连接 CLI

1. 打开 **设置 → CLI 连接**，选择 Claude Code 或 Kiro CLI。
2. 点击 **连接**，未登录时按提示完成登录。找不到 CLI 时填写可执行文件的绝对路径。
3. 连接成功后，在弹窗中选择默认模型和思考强度，也可展开为角色单独设置。之后可在 CLI 详情页的「模型与思考强度」卡片修改默认值。

第一个成功连接的 CLI 会自动设为默认，可在「CLI 连接」总览切换。面板新对话可选角色，自动带出该角色的 CLI、模型和思考强度，也可为当前对话单独调整。未选角色时预选可用的默认 CLI。

两个 CLI 各自保存可执行文件路径。只用 Claude Code 时，只需安装并连接 Claude Code，无需安装 Kiro CLI 或配置 Kiro 的代理默认值。Claude 任务使用 Claude Code 自身的网络配置，并继承启动环境中已有的代理变量。

已连接的 CLI 可以暂停、启动或断开。**测试调用** 会消耗少量模型额度，按需使用。

Claude 的模型列表读取当前 CLI 配置的 API 地址（包括代理/中转），可在此保存默认模型和思考强度；Kiro 继续读取账户模型目录。若 API 不支持模型目录或只使用订阅登录，页面会说明限制，不用固定列表替代。思考强度是 CLI 选项，实际支持情况由执行时验证。

Claude 额度栏可点击“刷新”，从当前项目生效的 CLI API 地址查询 Sub2API 兼容的 `/v1/usage`。显示接口提供的已用量、上限或余额，以及更新时间；只有明确返回重置时间才显示“几h 几m 后重置”的倒计时，缺失时显示“重置时间未知”。切换 API 地址后查询随之切换，不固定服务商域名。不支持该协议或无法复用认证时会显示原因，普通页面轮询不请求外部额度接口。

## 3. 配置角色

在 **设置 → Subagent 角色** 中编辑内置角色，或新增自定义角色。每个角色可以选择 CLI、模型和思考强度，并设置职责与交付要求。

- **架构师**：制定技术方案、接口和模块边界。
- **编码**：实现业务代码，根据测试反馈修复问题。
- **测试**：编写测试脚本，编码完成后执行测试、反馈并复测。
- **代码审查**：独立审查改动、风险和测试缺口。

角色配置全局生效，保存后在下次委派时使用。Codex 负责派遣、安排执行顺序、审核和最终验收。

## 4. 让 Codex 使用

1. 在 **设置 → Codex 技能** 中复制安装提示词。
2. 在本项目的 Codex 对话中发送提示词，完成一次全局 Skill 安装。
3. 安装后新建 Codex 对话，即可在其他项目中使用。

例如，对 Codex 说：

> 使用 $crewpane，让编码和测试角色完成登录功能，由你协调并验收。

面板中的直接消息用于补充任务指令、排查问题和查看执行结果；完整开发任务建议交给主 Agent 统一协调。

界面会显示任务角色。续聊读取最新角色职责；面板里手动调整过的对话沿用自己的 CLI、模型和思考强度，其他角色对话继续跟随角色配置。Codex 派发任务必须指定角色，并使用角色配置的 CLI、模型和思考强度。

执行中的任务可单独停止，已修改的项目文件保留；异常退出的任务在确认进程已结束后标记中断。失败时可打开诊断并复制给 Codex，权限不足不会自动扩权或重新提交。

Codex 也可以通过统一命令管理任务：

```bash
python3 -m crewpane tasks list
python3 -m crewpane tasks show --run-dir /path/to/run
python3 -m crewpane tasks stop --run-dir /path/to/run
```

任务启动时自动登记项目和日志目录，因此独立 worktree 或自定义日志位置的任务也能在面板中查看。

## 5. 浏览和编辑项目

点击左侧项目名称旁的 **浏览项目**，在顶栏切换 **文件** 和 **Git 改动**。将鼠标移到文件夹上，或用键盘聚焦该行，即可在该目录中新建文件或文件夹；文件和文件夹行都可复制绝对路径。Git 改动按已暂存、未暂存和未跟踪分组。

在仓库根目录的 **Git 改动** 页，点文件旁的 **+** 暂存或 **−** 取消暂存，分组标题上的图标可对该组批量操作。输入提交说明后点 **提交**，只提交暂存区。源代码管理标题旁的分支图标可新建或切换本地分支。面板提交不运行 Git 钩子，也不签名。需要钩子或签名的提交请在终端执行。

在 **设置 → GitHub** 检查本机 [GitHub CLI](https://cli.github.com/) 的登录状态。未登录时，点击 **登录 GitHub**，复制设备码并在 GitHub 网页确认授权。凭据由 GitHub CLI 保管，当前系统用户下的项目可复用；终端切换账号后可在面板点 **刷新状态**。

项目使用标准的 `https://github.com/组织/仓库.git` 远端时，「Git 改动」会显示上游和相对于上次获取的提交数（`↓` 待拉取，`↑` 待推送）。云朵按钮只获取远端状态；`↓` 只做快进拉取；`↑` 推送当前已提交内容，首次推送会确认目标并设置上游。右侧图标可在 GitHub 打开仓库。不执行强制推送；分支分叉、SSH 或自定义远端设置请在终端处理。

左右对照和行内 Diff 都显示完整上下文，打开时跳到第一处改动。右侧滚动条旁的概览用红色标出删除、绿色标出新增，点击可跳转。

文件树会用颜色和字母标记 Git 改动（例如黄色 `M` 表示修改），含改动的文件夹会显示圆点。被仓库的 Git 规则忽略的条目显示为灰色。磁盘上的文件被其他程序修改后，可以刷新文件树来更新状态。

单击文件会复用预览标签；双击文件或开始编辑，就会保留该标签。可以同时打开多个文件，切换标签时会保留各自的编辑内容和光标位置。

在 Monaco 中用 **Ctrl+S / ⌘S** 保存。若磁盘上的文件已经变化，面板会提示冲突并保留编辑内容。编辑器右上角的更多菜单可重新载入文件或将文件移到回收站。

在 Linux 上可以用系统文件管理器恢复移到回收站的文件。若项目和回收站位于不同文件系统，删除会取消。编辑器保存只更新磁盘文件，不会暂存或提交。

## 6. 关闭与重新打开

安装 Skill 后，可以直接对 Codex 说：

> 关闭 crewpane 面板。

> 启动 crewpane，打开面板。

也可在 **设置 → 服务与资源** 中关闭服务。

也可以在项目目录终端中手动执行：

```bash
python3 -m crewpane start   # 后台启动
python3 -m crewpane stop    # 关闭服务
```

关闭面板服务会保留 CLI 连接、角色配置和历史记录，正在运行的 CLI 任务继续执行。
